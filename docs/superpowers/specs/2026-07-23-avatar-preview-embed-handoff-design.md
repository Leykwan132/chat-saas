# Avatar Preview and Embed Handoff Design

## Status

Approved on 2026-07-23.

This refinement supersedes the earlier requirement that the configured Avatar
home page show no embed snippet. It does not restore LiveAvatar Embed V2 or the
provider's default UI.

## Goal

Show customers a clearly labeled preview of their custom KiloBot Avatar and a
copyable website embed snippet on the same configured Avatar home page.

## Configured Home Page

The configured Avatar home page uses a responsive two-column layout.

The left column contains:

- A small `Preview` heading.
- The existing custom 16:9 `AvatarVideoStage`.

The right column contains:

- An `Embed on your website` heading.
- A concise instruction explaining that the code adds the Avatar to a website.
- A copyable iframe snippet.

The preview remains the visually dominant column. The embed panel uses a
bounded width suitable for code, aligns to the top of the preview, and may use
a restrained border and background to separate instructions from the live
stage. On narrower screens, the embed panel stacks below the preview.

The page header, Beta badge, product description, and permission-aware
`Edit avatar` action remain unchanged.

## Embed Contract

The snippet is generated by:

```ts
buildAvatarEmbedSnippet(configuration.publicKey)
```

It points to:

```text
/avatar/embed/:publicKey
```

The iframe therefore loads the complete custom KiloBot experience, including:

- The custom video stage.
- The custom start and active controls.
- The backend-issued LiveAvatar session token flow.
- KiloBot transcription, Inbox conversation creation, reply delivery, and
  `repeat` playback.

The snippet includes microphone and autoplay permissions and preserves a 16:9
responsive aspect ratio. It never uses `configuration.embedUrl`, a provider
Embed V2 URL, or HeyGen's default embedded UI.

The host website controls the iframe's placement and dimensions. The embedded
cross-origin UI remains styled and controlled by KiloBot.

## Feature Flag

`enable_avatar_feature` gates both halves of the handoff:

- Disabled dashboard users cannot access the Avatar home page or its embed
  snippet.
- Disabled public embed requests render `Avatar unavailable`.

The feature flag remains a frontend rollout gate rather than a backend
authorization boundary.

## Component Boundary

Replace the legacy provider-oriented `AvatarEmbedCard` contract with a focused
custom embed panel that accepts `publicKey`.

The configured page owns the responsive preview-and-embed layout. The
`AvatarVideoStage` remains responsible only for the interactive preview. The
embed panel remains responsible only for snippet generation, display, and
clipboard feedback.

No touched code file may exceed 300 lines.

## Testing

Implementation follows red-green-refactor and verifies:

- The configured page labels the live stage `Preview`.
- The custom embed panel appears to the right at desktop widths and below the
  preview on narrow widths.
- The panel accepts `publicKey` and calls `buildAvatarEmbedSnippet(publicKey)`.
- The snippet contains the KiloBot public embed route, microphone permission,
  autoplay permission, and a 16:9 aspect ratio.
- Copy writes the exact generated snippet and confirms success.
- The configured page does not read `configuration.embedUrl`.
- The provider snippet builder and provider iframe are not used by the
  configured home page.
- Avatar feature-flag navigation and route gates remain green.
- Scoped lint, production build, line limits, stale-provider scans, and
  whitespace checks pass.
