# Agent Setup

<DocVerified date="2026-07-28" />

Agent Setup defines who the agent is, how it communicates, and when it should involve a person. Keep business facts in [Knowledge Base](/build-your-agent/knowledge-base) and use [Workflows](/automate/send-messages-and-assets) for requests that must perform an action.

<DocOutcomes>

### By the end, you will

- Decide where instructions, facts, and actions belong
- Write clear behavior, tone, boundaries, and escalation rules
- Review changes before publishing the agent

</DocOutcomes>

## Best practice

Keep Agent Setup focused on behavior: define the role, tone, boundaries, and escalation rules. Put durable business facts in the Knowledge Base and actions in Workflows so each change is easier to review and test.

## Decide where information belongs

| Put it in | Use it for | Example |
| --- | --- | --- |
| Agent Setup | Role, goals, tone, boundaries, escalation | “Never diagnose a medical condition.” |
| Knowledge Base | Durable facts the agent may answer from | Opening hours, pricing, policies |
| Workflow | A defined condition that performs an action | Send a brochure or book an appointment |

## Write the system prompt

A useful prompt identifies the agent, audience, goals, conversation behavior, knowledge limits, and handoff boundary.

<DocExample title="Weak prompt">

`You are a helpful dental assistant. Answer questions and get bookings.`

This leaves the audience, knowledge boundary, escalation behavior, and acceptable booking behavior unclear.

</DocExample>

<DocExample title="Northstar Booking Assistant system prompt">

```text
You are Northstar Booking Assistant for Northstar Dental.

Help prospective and existing patients understand approved clinic information
and take the next appropriate step.

Use the Knowledge Base for business facts. If the answer is missing or
conflicting, say that you do not have confirmed information and offer a human
handoff. Never invent services, prices, availability, medical advice, diagnoses,
or treatment suitability.

Ask one clear question at a time. Keep answers concise, warm, and professional.
Use a Workflow when a matching request requires a brochure, booking, escalation,
or conversation closure.

Escalate urgent symptoms, complaints, payment disputes, privacy requests, and
requests for clinical judgment to a teammate.
```

</DocExample>

## Choose model and style

Open **Model & Style**, choose a model available to the workspace plan, and set response length, emoji use, formality, and humor. Style settings shape normal replies; exact Workflow messages remain exact.

## Control AI replies

Open **Triggers** and choose the available **Reply mode**. Human escalation or a conversation-level pause can prevent automatic replies even when the agent is published. Missing controls can indicate a plan, permission, or routing restriction.

## Publish

**Publish** makes the current draft active. Saving or editing a field does not guarantee that customers receive the new configuration. If you navigate away with an unpublished draft, return and publish the latest changes.

## Common problems

- **The answer is wrong:** correct conflicting Knowledge Base sources before expanding the prompt.
- **An action does not run:** check the Workflow condition and near-miss tests.
- **AI does not reply:** check conversation AI state, Reply mode, credits, permissions, and channel connection.
- **A change is absent:** confirm the draft was published.
