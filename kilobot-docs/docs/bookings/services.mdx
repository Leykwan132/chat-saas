# Services <span className="docs-required-tag">Required for auto booking</span>

<DocVerified date="2026-07-28" />

A Service combines customer-facing details, timing, booking fields, sales style, and teammate assignment. Availability and Calendar determine whether the assigned teammate can actually accept a requested time.

<DocOutcomes>

### By the end, you will

- Understand what each Service setting controls
- Choose timing, booking fields, sales style, and assignment
- Prepare a Service for agent booking

</DocOutcomes>

:::important
Auto booking needs a Service and an eligible teammate. KiloBot must know which Service to book before it can find a valid appointment time.
:::

## Service settings

| Setting | What it means |
| --- | --- |
| **Name and description** | The customer-facing name and explanation for the appointment. |
| **Active state** | Whether the Service can be used for new bookings. |
| **Duration** | How long the appointment itself lasts. |
| **Buffer** | Extra time held before the next appointment. |
| **Timezone and preferred times** | How KiloBot interprets the schedule and which times it should prefer. |
| **Booking fields** | The questions KiloBot asks to collect the information the team needs. |
| **Sales style** | How the agent presents the Service: Proactive, Neutral, or Gentle. |
| **Assignment** | How KiloBot chooses an eligible teammate, such as the conversation owner, balanced load, round robin, or a specific teammate. |

<DocExample title="Northstar Consultation">

- **Duration:** 30 minutes
- **Buffer:** 15 minutes
- **Required fields:** Customer name, phone number, reason for visit
- **Assignment:** Conversation owner first

</DocExample>

Keep conversational data collection short. Default booking context includes date, time, customer name, and phone number; add text, number, select, yes/no, date, time, or phone fields only when the team will use them.

## Choose an assignment strategy

| Strategy | Choose it when |
| --- | --- |
| Conversation owner first | The existing relationship should take priority |
| Balanced | Work should favor teammates with less assigned load |
| Round robin | Eligible teammates should rotate predictably |
| Specific teammate | One person exclusively owns the Service |

Availability remains required for every strategy.
